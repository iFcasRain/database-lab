# 第七至九周复现说明

本说明用于从零复现 v1.0 应用，供其他同学或评审按步骤验收。执行完成后应当得到：迁移后的数据库、可运行的 Web 应用、34 项通过的自动化测试和 9 张界面截图。

## 1. 复现目标

| 目标 | 验收标准 |
|---|---|
| 数据库迁移到 v1.0 | `regression.sql` 显示“v1.0 回归通过”，23 项检查全部 PASS |
| Web 应用可启动 | 浏览器打开 `http://127.0.0.1:5000` 出现登录页 |
| 四个角色可登录 | `manager01` / `cashier01` / `stock01` / `member01` 均能登录并看到各自的工作台 |
| 关键流程可演示 | 门店下单扣库存、顾客线上下单、确认收款、库存盘点、商品维护 |
| 自动化测试通过 | `python tests/test_app.py -v` 输出 `Ran 34 tests ... OK` |

## 2. 执行前检查

1. SQL Server 服务已启动，`.\SQLEXPRESS` 可连接；
2. 已安装 Python 3.10+ 与 ODBC Driver 18；
3. `database-lab` 目录下有 `requirements.txt`、`.env.example`、`app/`、`sql/`、`tests/`；
4. 确认 `ConvenienceStoreDB` 只用于本实验（若不是，先备份）。

## 3. 执行顺序总览

```text
① 安装依赖        python -m pip install -r requirements.txt
② 配置            copy .env.example .env  并修改 DB_SERVER / DB_DATABASE
③ 建库与 v0.1     00 → 01 → 02 → 03 → 04 → query → view → constraint → role → v01_acceptance
④ 迁移            migration.sql
⑤ 回归            regression.sql
⑥ 启动应用        python run.py
⑦ 浏览器验收      四个角色各走一遍
⑧ 自动化测试      python tests/test_app.py -v
```

## 4. 第一步 安装依赖

```bash
cd database-lab
python -m pip install -r requirements.txt
python -c "import flask, pyodbc; print(flask.__version__, pyodbc.version)"
```

预期输出类似 `3.1.3 5.5.0`。

## 5. 第二步 配置

```bash
copy .env.example .env
```

至少确认三项：

- `DB_SERVER` 与本机实例名一致；
- `DB_DATABASE=ConvenienceStoreDB`；
- `DB_TRUSTED_CONNECTION=true`（使用 Windows 身份验证）。

## 6. 第三步 建库与 v0.1

在 SSMS 中按 README 的顺序执行 `sql/` 下前十个脚本。关键检查点：

| 脚本 | 预期 |
|---|---|
| `01_create_tables.sql` | 12 张表创建成功 |
| `02_add_constraints.sql` | 约束清单返回 92 项 |
| `03_insert_sample_data.sql` | 各表行数与样例一致，纯牛奶显示“需要补货” |
| `04_crud.sql` | 商品/库存/订单 CRUD 结果符合预期 |
| `constraint.sql` | 8 项测试全部 PASS |
| `role.sql` | 6 项权限测试全部 PASS |
| `v01_acceptance.sql` | 9 项检查全部 PASS，显示“v0.1 验收通过” |

## 7. 第四步 执行迁移

在 SSMS 中打开并执行 `sql/migration.sql`。脚本会输出 8 个步骤，逐项核对：

| 步骤 | 预期输出 |
|---|---|
| 1 | 三组基线查询：订单金额、商品销量、库存 |
| 2 | 12 张表的字段数与“保持 v0.1” |
| 3 | `app_user 表已创建。` |
| 4 | 无输出（3 个视图创建成功） |
| 5 | 无输出（7 个索引创建成功） |
| 6 | `已为当前登录名授予应用账号的 IMPERSONATE 权限。` |
| 7 | 无输出（5 个账号写入成功） |
| 8 | 表 13、视图 3、角色 5、账号 5，以及账号清单 |

若第 3 步输出“app_user 表已存在，本次跳过创建”，说明此前已经迁移过，属正常现象。

## 8. 第五步 执行回归

执行 `sql/regression.sql`，应当看到两张结果表（19 项 + 4 项）全部 `PASS`，汇总行为 `pass_count = 23`、`fail_count = 0`，最后一行显示“v1.0 回归通过”。

保存证据：

- `result/week6_02_regression_output.txt`（可直接复制结果窗口文本）

## 9. 第六步 启动应用

```bash
python run.py
```

看到 `小卖部经营管理 v1.0 已启动：http://127.0.0.1:5000` 后打开浏览器。若出现“数据库应用账号 app_auth 不可用”，说明迁移未执行或 `.env` 中的账号名不一致。

```bash

```

```text

```

## 12. 常见问题

| 现象 | 处理 |
|---|---|
| `ModuleNotFoundError: No module named 'flask'` | 未安装依赖，回到第三步 |
| 页面显示“系统配置不完整” | 检查 `.env` 的账号名是否与 `migration.sql` 一致 |
| 登录成功但所有页面 500 | 查看 `logs/app.log`，通常是 `IMPERSONATE` 未授权 |
| 测试报“库存不足”相关失败 | 样例库存被改过，重新执行 `03` 与 `04` 恢复样例数据 |
| 迁移后重跑 `v01_acceptance.sql` 显示 FAIL | 该脚本检查的是 v0.1 状态（12 张表），迁移后表数为 13 属于预期；迁移后用 `regression.sql` 验收 |
| 端口占用 | `set PORT=8080` 后重启 |
