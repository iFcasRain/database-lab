# 第四周 SQL Server 实验步骤

## 1. 本周目标

在第三周数据库基础上完成多表连接、聚合统计、子查询、统计视图、完整性正反例和最小权限角色测试，并运行 v0.1 阶段验收脚本。

## 2. 执行前检查

开始前在 SSMS 中确认：

1. 当前连接仍为 `localhost`。
2. 数据库下拉框选择 `ConvenienceStoreDB`。
3. 第三周五个脚本已经全部成功执行。
4. 正式数据仍为 3 个商品、3 张订单和 5 条订单明细。

第四周脚本均可重复运行，但第一次实验仍应严格按以下顺序执行。

## 3. 执行顺序

| 顺序 | 脚本 | 主要内容 |
|---:|---|---|
| 1 | `query.sql` | 多表连接、聚合、HAVING、子查询及库存和采购查询 |
| 2 | `view.sql` | 创建并查询 4 个统计视图 |
| 3 | `constraint.sql` | 补充格式约束，执行 1 个合法和 7 个非法测试 |
| 4 | `role.sql` | 创建 3 个角色并执行正常与越权测试 |
| 5 | `v01_acceptance.sql` | 集中检查表、视图、角色、数据和关键规则 |

## 4. 第一步 运行 query.sql

打开并完整执行 `sql/query.sql`。脚本会依次返回：

1. 订单详情连接查询，非会员订单显示“非会员”。
2. 商品销量、销售额和订单数统计。
3. 使用 `HAVING` 筛选累计销量不少于 3 件的商品。
4. 会员完成订单数量和消费金额。
5. 实付金额高于平均值的订单。
6. 库存状态和建议补货数量。
7. 采购单、供应商、创建人、审批人和商品明细。
8. 从未出现在已完成订单中的商品。

## 6. 第三步 运行 constraint.sql

打开并完整执行 `sql/constraint.sql`。脚本会补充商品编码和手机号格式约束，然后执行：

- 合法商品和库存写入成功；
- 负价格失败；
- 不存在的分类失败；
- 重复条码失败；
- 负库存失败；
- 完成订单缺少支付方式失败；
- 订单明细数量为 0 失败；
- 错误手机号失败。

测试数据均在事务中回滚，不会改变正式数据。最终结果表中 8 行 `actual_result` 应全部为 `PASS`。

## 10. 故障处理

1. 查询脚本提示对象不存在：确认数据库为 `ConvenienceStoreDB`，并检查第三周脚本是否完整执行。
2. `role.sql` 提示视图不存在：先执行 `view.sql`。
3. 权限测试中某项显示 `FAIL`：保留完整错误信息，不要手工扩大权限；先核对角色授权语句。
4. 约束测试中合法用例失败：检查前面补充约束是否与现有样例数据冲突。
5. 再次执行角色或约束脚本：脚本会复用已有角色、用户和约束，不会重复创建。
