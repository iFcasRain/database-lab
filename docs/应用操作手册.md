# 应用操作手册（v1.0）

本手册面向第一次接触本项目的同学，目标是在一台只装了 SQL Server 的 Windows 电脑上，从零把数据库和应用跑起来，并完成各角色的主要业务操作。

## 1. 运行环境

| 项目 | 要求 | 本项目验证环境 |
|---|---|---|
| 操作系统 | Windows 10/11 | Windows 11 |
| 数据库 | SQL Server 2017 及以上（含 Express） | SQL Server 17.0（`.\SQLEXPRESS`） |
| Python | 3.10 及以上 | 3.12 |
| 浏览器 | 支持 ES2020 的现代浏览器 | Microsoft Edge |
| ODBC 驱动 | Microsoft ODBC Driver 18 for SQL Server | 已随 SQL Server 客户端工具安装 |

## 2. 安装依赖

```bash
cd database-lab
python -m pip install -r requirements.txt
```

`requirements.txt` 只包含两个依赖：`Flask`（Web 框架）与 `pyodbc`（SQL Server 驱动）。

## 3. 配置

复制配置样例并修改：

```bash
copy .env.example .env
```

`.env` 中需要关心的项：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `APP_SECRET_KEY` | 示例值 | 会话签名密钥，正式使用必须改成随机字符串 |
| `DB_SERVER` | `.\SQLEXPRESS` | SQL Server 实例名 |
| `DB_DATABASE` | `ConvenienceStoreDB` | 数据库名 |
| `DB_TRUSTED_CONNECTION` | `true` | 使用 Windows 身份验证（推荐） |
| `DB_APP_USER_*` | `app_auth` 等 | 迁移脚本创建的应用账号名，一般不需要改 |
| `POINTS_PER_YUAN` / `POINTS_PER_DISCOUNT_YUAN` | 1 / 10 | 积分规则 |

数据库连接信息只出现在配置文件中，页面和业务代码里没有服务器地址或口令。

## 4. 准备数据库

在 SSMS 或 sqlcmd 中按顺序执行（与前几周一致）：

```text
sql/00_create_database.sql
sql/01_create_tables.sql
sql/02_add_constraints.sql
sql/03_insert_sample_data.sql
sql/04_crud.sql
sql/query.sql
sql/view.sql
sql/constraint.sql
sql/role.sql
sql/v01_acceptance.sql      ← 应显示“v0.1 验收通过”
sql/migration.sql           ← 新增 app_user、应用视图、角色与账号
sql/regression.sql          ← 应显示“v1.0 回归通过”
```

> 若数据库已经存在且已迁移过，只需确认 `regression.sql` 通过即可，不要重复执行 `01`、`03`（这两支脚本检测到已有对象会主动停止，属于保护机制）。

迁移脚本会自动为“当前执行脚本的登录名”授予应用账号的 `IMPERSONATE` 权限。如果应用使用另一个 Windows 账户运行，需要由管理员手工执行：

```sql
GRANT IMPERSONATE ON USER::app_auth TO [你的登录名];
GRANT IMPERSONATE ON USER::app_customer TO [你的登录名];
GRANT IMPERSONATE ON USER::app_cashier TO [你的登录名];
GRANT IMPERSONATE ON USER::app_inventory TO [你的登录名];
GRANT IMPERSONATE ON USER::app_manager TO [你的登录名];
```

## 5. 启动应用

```bash
python run.py
```

看到 `小卖部经营管理 v1.0 已启动：http://127.0.0.1:5000` 后，用浏览器打开该地址。

可用环境变量覆盖监听地址：`set HOST=0.0.0.0` 与 `set PORT=8080`（Windows）。

健康检查：访问 `http://127.0.0.1:5000/api/health`，返回 `{"success": true, "data": {"status": "ok"}}` 表示数据库连接与应用账号都正常。

## 6. 演示账号

| 用户名 | 初始口令 | 角色 | 绑定对象 |
|---|---|---|---|
| `manager01` | `Manager@2026` | 店长 | 员工 E001 陈店长 |
| `cashier01` | `Cashier@2026` | 店员 | 员工 E002 刘收银 |
| `stock01` | `Stock@2026` | 库存管理员 | 员工 E003 赵理货 |
| `member01` | `Member@2026` | 顾客 | 会员 M001 张晓雨（120 分） |

## 7. 角色操作指引

### 7.1 店员（cashier01）：门店结算下单

1. 登录后进入“工作台”，可看到“待支付订单”和“低库存提醒”；
2. 点击“去结算下单”或顶部“订单”；
3. 在“门店结算下单”区域选择商品、填写数量，点击“加入清单”；
4. 可选填写会员号（例如 `M001`）与“使用积分抵扣”（10 的倍数）；
5. 选择支付方式后点击“提交订单”；
6. 提交成功后跳转订单详情，状态为“已完成”，库存已扣减，会员积分已结算。

**这条流程同时写入**：订单、订单明细、库存数量、库存流水（`SALE_OUT`）、积分流水（`REDEEM` / `EARN`）与会员余额，全部在同一个事务中。

### 7.2 顾客（member01）：线上下单

1. 登录后进入“工作台”，可看到本人会员号、积分余额和最近积分流水；
2. 点击“线上下单”；
3. 选择商品加入清单，提交订单；
4. 订单状态为“待支付”，此时**不扣库存、不结算积分**；系统自动指派一名当班收银员作为经办人；
5. 如改变主意，可在订单列表点击“取消”，订单变为“已取消”。

### 7.3 店员：确认收款

1. 在“工作台”的“待支付订单”或“订单”列表中点击“处理/详情”；
2. 点击“确认收款”，输入支付方式（`CASH` / `MOBILE` / `CARD`）与积分抵扣；
3. 确认后订单变为“已完成”，此时才扣减库存并结算积分。

### 7.4 库存管理员（stock01）：库存盘点

1. 登录后进入“工作台”，看到需要补货的商品；
2. 点击“查看库存”进入库存页；
3. 在目标商品行点击“盘点调整”，填写“盘点后数量”和“调整原因”；
4. 提交后库存数量更新，并自动写入一条 `COUNT_GAIN`（盘盈）或 `COUNT_LOSS`（盘亏）流水。

数量没有变化时系统会拒绝提交，避免产生无意义的流水。

### 7.5 店长（manager01）：商品维护与经营分析

**新增商品**：商品页 → “新增商品” → 填写编码（`P` + 3 位数字）、条码（8—32 位数字）、名称、分类、单位、售价、初始库存、预警值 → 保存。系统会在同一事务中同时创建商品与库存记录。

**修改商品**：商品页 → 目标行“编辑” → 修改名称、分类、单位、售价或状态 → 保存。编码与条码不可修改，修改售价不会影响历史订单的成交单价。

**停用商品**：编辑商品把状态改为“停用”。顾客端不再显示该商品，下单时会提示“已停用”。这比直接删除更符合业务（保留历史订单引用）。

**经营分析**：顶部“经营分析”可查看今日/累计订单与销售额、商品与会员总数、低库存清单、销售排行榜。

## 8. 界面与权限对照

| 页面 | 顾客 | 店员 | 库存管理员 | 店长 |
|---|:--:|:--:|:--:|:--:|
| 工作台 | ✓ | ✓ | ✓ | ✓ |
| 商品 | ✓（只读，仅在售） | ✓（只读） | ✓（只读） | ✓（可维护） |
| 库存 | ✗ | ✓（只读） | ✓（可盘点） | ✓（可盘点） |
| 订单 | ✓（仅本人，可线上下单） | ✓（全部，可结算/确认/取消） | ✗ | ✓（全部） |
| 会员 | ✗ | ✓ | ✗ | ✓ |
| 经营分析 | ✗ | ✗ | ✗ | ✓ |

无权访问的页面会显示“当前角色无权访问该页面”，接口返回 403 并带有错误码 `FORBIDDEN`。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面提示“数据库应用账号 app_auth 不可用” | 未执行 `migration.sql`，或应用账号未创建 | 执行 `sql/migration.sql` |
| 页面提示“系统配置不完整，请联系管理员” | `.env` 中的数据库名或应用账号名写错 | 核对 `.env` 与 `migration.sql` |
| 登录提示“用户名或密码不正确” | 口令大小写敏感 | 使用第 6 节的初始口令，注意 `@` 与大小写 |
| 提示“当前登录名没有 IMPERSONATE 权限” | 应用运行账户与执行迁移的账户不同 | 按第 4 节手工授权 |
| `python run.py` 报 `ImportError: flask` | 依赖未安装 | `python -m pip install -r requirements.txt` |
| 端口 5000 被占用 | 其他程序占用 | `set PORT=8080` 后重新启动 |
| 下单提示“库存不足” | 库存确实不够，或被其他会话锁定 | 在库存页核对数量 |
| 提示“订单状态已被其他操作改变” | 两位店员同时处理同一张待支付订单 | 刷新页面后重试 |

## 10. 日志查看

应用日志位于 `logs/app.log`。每条日志都带请求号，可与页面错误提示中的“请求号”对应：

```text
2026-11-09 17:12:04,340 | WARNING | req=61897f595f16 | user=manager01 | role=MANAGER | app | 业务异常：code=VALIDATION_ERROR，path=/api/products，message=所选分类不存在或已停用
```

需要定位具体失败原因时，按请求号在日志中搜索即可看到完整链路；前端永远只显示友好提示。
