## 9. 协作规则

1. 每个人提交前先检查文件是否能正常显示，表名和字段名是否与数据字典一致。
2. 修改公共设计前先在组内说明，避免同一对象出现两套命名。
3. 一项工作至少由另一名成员检查一次，检查结果写入提交说明或 AI 使用记录。
4. 后续 SQL 必须以第二周数据字典为唯一依据；如果需要改变字段，应先同步修改数据字典。
5. 第 5 周之后的任何结构调整都必须走 `migration.sql`，不允许直接改 `01_create_tables.sql` 掩盖历史。
6. 应用代码中的 SQL 只允许出现在 `app/db/`，提交前用 `grep` 自查一次。
