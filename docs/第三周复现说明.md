# 第三周 SQL Server 实验步骤

## 1. 本周目标

从空数据库开始创建小卖部数据库及 12 张业务表，添加主码、候选码、外码、非空、默认值和检查约束，装载相互关联的样例数据，并演示商品、库存和订单的新增、查询、修改与删除。

## 2. 实验前准备

1. 启动 SQL Server 服务。
2. 打开 SQL Server Management Studio，简称 SSMS。
3. 在“连接到服务器”窗口中选择“数据库引擎”。
4. 服务器名称优先尝试 `localhost` 或 `.`，身份验证按课堂环境选择 Windows 身份验证。
5. 连接后先新建查询，执行：

```sql
SELECT @@SERVERNAME AS server_name,
       @@VERSION AS version_info,
       SUSER_SNAME() AS current_login;
```

能够返回服务器名、版本和当前登录名后，再开始运行项目脚本。此处建议保存一张连接成功截图。

## 3. 脚本位置

所有第三周脚本都在仓库的 `sql` 目录中：

| 顺序 | 脚本 | 作用 |
|---:|---|---|
| 1 | `00_create_database.sql` | 创建或进入 `ConvenienceStoreDB` |
| 2 | `01_create_tables.sql` | 创建 12 张空表以及主码、候选码和默认值 |
| 3 | `02_add_constraints.sql` | 添加外码和检查约束 |
| 4 | `03_insert_sample_data.sql` | 插入与第二周文档一致的样例数据 |
| 5 | `04_crud.sql` | 演示商品、库存和订单 CRUD |

必须按以上顺序执行，不要一次只选中脚本的一小段执行。

4. 结果中应显示当前数据库为 `ConvenienceStoreDB`。
5. 在对象资源管理器中右键“数据库”并刷新，应能看到该数据库。

截图建议：对象资源管理器中的数据库名称，以及脚本下方显示数据库名、登录名和时间的结果。

1. 打开并完整执行 `sql/01_create_tables.sql`。
2. 结果应列出 12 张表，并且行数均为 0。
3. 刷新 `ConvenienceStoreDB → 表`，应能看到 `dbo.category` 等 12 张表。

截图建议：对象资源管理器中的表清单，以及结果区域中的 12 个表名。

截图建议：约束查询结果中同时出现 `FOREIGN_KEY_CONSTRAINT` 和 `CHECK_CONSTRAINT`。

### 步骤四 装载样例数据

截图建议：样例数据插入成功、各表行数、低库存商品三部分。

## 5. 正确结果检查

执行全部脚本后，在新查询窗口运行：

```sql
USE ConvenienceStoreDB;

SELECT COUNT(*) AS table_count
FROM sys.tables
WHERE schema_id = SCHEMA_ID(N'dbo');

SELECT COUNT(*) AS product_count FROM dbo.product;
SELECT COUNT(*) AS order_count FROM dbo.sales_order;
SELECT COUNT(*) AS order_item_count FROM dbo.sales_order_item;

SELECT p.product_code, p.product_name, i.quantity, i.reorder_level
FROM dbo.product AS p
JOIN dbo.inventory AS i ON i.product_id = p.product_id
ORDER BY p.product_id;
```

预期结果：

- `table_count = 12`
- `product_count = 3`
- `order_count = 3`
- `order_item_count = 5`
- 商品 P002 的库存为 8，预警值为 10

## 6. 常见问题

### 提示数据库已存在

`00_create_database.sql` 不会删除已有数据库。第一次执行后再次运行只会提示数据库已经存在，这是正常情况。

### 提示目标表已存在

`01_create_tables.sql` 为保护数据会主动停止。若需要重新做“从空数据库复现”，不要手工逐表乱删；先确认该数据库只用于本实验，再使用 SSMS 删除整个 `ConvenienceStoreDB`，然后从脚本 00 重新开始。

### 提示已有样例数据

`03_insert_sample_data.sql` 会阻止重复插入。说明脚本已经成功执行过，不需要重复运行。若必须重新演示，应使用新的空数据库复现。

### 出现外码冲突

通常是脚本顺序错误或前一步只执行了一部分。检查分类、商品、会员、员工等主表数据是否已成功插入，再从干净数据库按顺序复现。

### CRUD 后正式数据发生变化

库存修改使用事务回滚，测试商品和测试订单会在演示末尾删除。正常执行后正式样例数据数量应仍为 3 个商品、3 张订单和 5 条订单明细。
